# 麦门人格 · 口味年报

> 麦当劳每年给你一份消费账单，但它从来不告诉你——
> 你在深夜 23:40 点的那份巨无霸，到底是在填饱肚子，还是在给自己收尾。

把一个人的麦当劳订单流水，变成一份**关于他自己的报告**。

不是省钱工具，不是点餐助手。是**一面镜子**。

`麦门人格` 读取你真实的历史订单，从四个可测量的维度——**忠诚、规律、犒赏、精算**——算出你在这件事上的行为形状，落到 13 个人格中的一个，然后**把判断依据一条条摊开给你看**。

它不会说"你是深夜型人格，你一定很孤独"。它会说：**你有 20% 的订单发生在 21 点之后，最常出现的时间是 23 点，而那一单里，巨无霸依然是你的默认答案（共 48 次）。**

事实在前，解读在后。

## 它长什么样

跑完一条命令，得到两份报告：

| 文件 | 用途 |
| --- | --- |
| `reports/report.html` | 可截图分享的完整报告（单文件，离线可开） |
| `reports/report.md` | 终端 / 文本版，同样内容，便于贴到任何地方 |

报告在浏览器里长这样（`--demo` 演示数据的输出）：

```
记  肌肉记忆型点单员                      麦门人格
    Muscle-Memory Orderer                    2026
    券在哪、怎么叠、点哪个——你的手比脑子快。

    2025-10-29 — 2026-10-20 · 229 笔订单 · 180 个活跃日

────────────────────────────────────────────
忠诚  ████████████████████████ 91  主导
精算  ██████████████████ 84
规律  ██████████ 45
犒赏  ████████ 36
────────────────────────────────────────────
```

> 第一次跑请务必加 `--demo`，它用内置演示数据，**不需要 MCP Token**，可以先把报告样式看完。

## 快速开始

### 方式一：先看效果（零配置，30 秒）

```bash
git clone https://github.com/lvyahao/mcd-taste-portrait.git
cd mcd-taste-portrait
python src/main.py --demo
```

只用 Python 标准库，**没有任何第三方依赖**，不需要 `pip install`。

打开 `reports/report.html` 就能看到一份完整报告。

### 方式二：用你自己的真实订单

**第 1 步 · 领取麦当劳 MCP Token**

到 <https://open.mcd.cn/mcp> 用手机号登录 → 右上角【控制台】→【激活】→ 复制 Token。免费。

**第 2 步 · 配置环境变量**

```bash
# macOS / Linux
export MCD_MCP_TOKEN=你的token

# Windows PowerShell
$env:MCD_MCP_TOKEN="你的token"

# Windows CMD
set MCD_MCP_TOKEN=你的token
```

**第 3 步 · 出报告**

```bash
python src/main.py
```

它会通过 MCP 拉取你的历史订单，分析，然后写出 `reports/report.html`。

**第 4 步（可选）· 接进 WorkBuddy**

把 `mcp-config.example.json` 里的 `YOUR_MCP_TOKEN` 换成真实 Token，粘进
WorkBuddy 的【自定义连接器 → 配置 MCP】，启用后就能直接对话：

> "用 mcd-taste-portrait 分析我的麦当劳订单，看看我是什么人格。"

## ⚠️ 关于订单来源（请先看这一条）

**麦当劳 MCP 只能读到你通过官方渠道（APP / 小程序 / 官网）下的单。**

如果你平时在柜台或自助点餐机买，账号里很可能一条记录都没有。
遇到这种情况，`python src/main.py` 会明确告诉你「这个账号没有可用的历史订单」，
**而不是假装生成一份报告**——这份报告的全部价值都在于它是真的，一旦它开始编，就没有意义了。

没有订单时有三条路：

1. `python src/main.py --demo` —— 用内置的 229 笔演示数据看效果
2. 换一个确实用小程序点过餐的账号领 Token
3. 用自己的数据：把订单整理成下面这个结构，用 `--input` 传入

```json
{
  "orders": [
    {
      "orderId": "20260314001",
      "createdAt": "2026-03-14T12:31:00+08:00",
      "channel": "pickup",
      "storeName": "麦当劳(中关村大街店)",
      "items": [
        {"name": "巨无霸", "qty": 1, "unitPrice": 26.0, "category": "burger"},
        {"name": "中薯条", "qty": 1, "unitPrice": 12.5, "category": "snack"}
      ],
      "originalPrice": 47.0,
      "payPrice": 31.0,
      "coupon": "超值三件套"
    }
  ]
}
```

```bash
python src/main.py --input my_orders.json
```

## 它怎么工作

```
麦当劳 MCP                    本项目                       产出
─────────────────────────────────────────────────────────────────
order-list          ──▶   collect.py（宽容解析）
query-meal-detail   ──▶        │
list-nutrition-foods──▶        ▼
                          analyze.py（四轴 + 13 型）
                               │
                    ┌──────────┴──────────┐
                    ▼                     ▼
              render_md.py          render_html.py
                    │                     │
                    ▼                     ▼
              report.md            report.html
```

技术上有三件事值得说：

**1. 不让大模型算数。**
人格判定全部是确定性代码：取数 → 计算 → 映射，同样的输入永远得到同样的输出。
你可以拿任意一笔订单去核对报告里的任何一个数字。

**2. 解析层是宽容的。**
MCP 的字段名在版本之间变过（`createdAt` / `orderTime` / `createTime`……
`items` / `productList` / `goodsList`……）。`collect.py` 用候选键 + 递归定位数组的方式解析，
并在 `src/probe.py` 里留了一个探针脚本，接口变了可以直接 dump 原始返回排查。

**3. 零依赖。**
`urllib` 手写 MCP Streamable HTTP 客户端（含 SSE 解析、`Mcp-Session-Id` 会话保持、429 限流识别）。
评审、路人、任何人 `git clone` 下来就能跑，不用配虚拟环境。

## 人格体系

四个轴，每个轴都在订单里能找到对应的行为痕迹：

| 轴 | 问的问题 | 数据来源 |
| --- | --- | --- |
| **忠诚** Loyalty | 你多常点同一批东西 | 搭配形态数 / 订单数、主品集中度、SKU 密度 |
| **规律** Ritual | 你的下单时间有多稳定 | 小时分布熵、主时段占比、最长连续天数、活跃密度 |
| **犒赏** Gratification | 你多常把这一单当作奖励 | 甜品咖啡占比、夜间占比、客单价、周末占比 |
| **精算** Optimizer | 你多常为价格动脑子 | 实付/原价、用券订单占比 |

主导轴 × 次导轴 → 13 型（12 个组合 + 1 个兜底）：

| 主导 | 次导 | 人格 | 印记 |
| --- | --- | --- | --- |
| 忠诚 | 规律 | 一号位守夜人 | 守 |
| 忠诚 | 犒赏 | 深夜的固定座位 | 座 |
| 忠诚 | 精算 | 肌肉记忆型点单员 | 记 |
| 规律 | 忠诚 | 午间齿轮 | 齿 |
| 规律 | 精算 | 周三点餐员 | 三 |
| 规律 | 犒赏 | 周五仪式官 | 仪 |
| 犒赏 | 忠诚 | 甜筒常客 | 甜 |
| 犒赏 | 规律 | 周末出门的理由 | 由 |
| 犒赏 | 精算 | 券后犒赏家 | 券 |
| 精算 | 规律 | 午市窗口猎人 | 猎 |
| 精算 | 忠诚 | 满减狙击手 | 狙 |
| 精算 | 犒赏 | 省下的钱买了麦旋风 | 省 |
| — | — | 菜单游牧民（数据太稀薄时兜底） | 野 |

**设计上刻意避开了两个坑：**

- **不算命。** 人格名是描述性的，不是诊断性的。报告结尾明确写着"人格是一种描述，不是一种诊断"。
- **不夸人。** 每个人格都配了一句"你的小毛病"，而且是从数据里长出来的（"你的优惠券用得比你的健身卡勤"）。

## 目标用户

- **想知道自己在吃这件事上是什么形状的人。** 不是为了省钱，是为了看到自己。
- **一年里点过 20 单以上麦当劳的人。** 低于这个量，数据撑不起一份报告（会落到"菜单游牧民"）。
- **做用户研究 / 数据分析的人。** 这是一个"把行为数据翻译成人话"的完整范例，四轴打分逻辑可以直接搬走。
- **麦当劳 MCP 的开发者。** `src/mcd_client.py` 是一个零依赖的 MCP Streamable HTTP 客户端实现，可以直接复用。

**它不适合谁：** 想找优惠券的人、想批量下单的人、想让 AI 替他决定吃什么的人。

## 隐私

- **Token 只从环境变量读**，不写进任何文件、不打印、不进 git。
- **订单数据只在本机内存里处理**，除了写进 `reports/` 下的报告文件，不会发往任何第三方。
- **报告里没有订单号、没有门店地址、没有手机号**，只有行为和统计。
- 如果你要把 `reports/report.html` 发出去，它就是一张关于你的、但不会泄露你的图。

## 已知限制

- 历史订单的可回溯范围取决于 MCP `order-list` 接口返回的条数上限，本项目的默认策略是尽量取全，取不满时报告会按实际区间计算。
- 营养数值来自公开资料的参考值（见 `src/nutrition_ref.py`），与门店实际出餐存在偏差，仅用于相对比较。
- 四轴的经验区间是按常见使用强度调的。如果你的订单极度集中在某一种模式（比如一年只点一种套餐），分数会顶到两端，人格判定仍然正确，但轴的区分度会下降。
- 这份报告不理解你的生活。它只理解你的订单。
